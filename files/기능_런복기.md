# 기능 설계 — 런 복기 / 실패 분석 메뉴

어드바이저와 별개인 **두 번째 큰 메뉴.** 상단에서 전환. 지난 런을 불러와 "왜 졌는지"를 한글로 피드백한다.

---

## 1. 흐름

1. **런 기록 불러오기** — 게임 런 히스토리(`...\saves\history`)에서 지난 런들을 읽어옴.
2. **런 목록 표시** — 날짜·캐릭터·결과(승/패)·도달 층·사망 원인을 카드 리스트로.
3. **런 하나 선택 → 자동 분석** — 아래 4가지 관점으로 진단.
4. **한글 피드백** — "왜 이렇게 됐는지 + 다음엔 어떻게"를 카드로 제시.

## 2. 분석 4관점 (모두 포함)

1. **덱 구성 문제** — 화력/방어/저주·저해 밸런스, 덱 크기, 아키타입 완성도. (예: "공격 카드 3장뿐 → 화력 부족")
2. **사망 지점 분석** — 어느 막·적·엘리트·보스에서 졌는지, 반복되는 사망 패턴.
3. **카드 선택 복기** — 런 기록의 픽/스킵 로그를 훑어 아쉬운 선택 지적. (기록에 픽/스킵이 남아 있으면 활용)
4. **유물 활용도** — 보유 유물 중 아키타입과 안 맞거나 못 살린 유물 지적.

## 3. 화면 구조

- **왼쪽:** 런 목록 (필터: 캐릭터/승패/기간). 각 항목에 승/패 배지 + 핵심 요약.
- **오른쪽(또는 하단):** 선택한 런의 상세 — 덱·유물 스냅샷 + 4관점 피드백 카드.
- 디자인 토큰(§14) 따름: near-black + 앰버 포인트, 승=초록 / 패=자주 절제 사용.

## 4. 단계적 구현

- **1단계 (규칙 기반, 지금 가능):** 런 기록에 든 정보만으로 4관점 판단. 정확한 인과는 아니지만 유용한 패턴 지적. 런 기록만 있으면 구현 가능.
- **2단계 (성공 사례 대조):** `기능_패턴학습.md`의 커뮤니티 데이터가 쌓이면 "비슷한 덱으로 이긴 사람은 이렇게 했다"로 고도화. ← 두 기능의 연결점.

## 5. 데이터

- 입력: 게임 런 히스토리 파일(JSON). 먼저 **실제 파일 하나를 열어 구조 확인**(덱·유물·층·사망·픽로그가 어디에 있는지) 후 파서 작성.
- 저장: 불러온 런을 앱 로컬에 캐시(다시 열 때 빠르게).

## 6. 주의

- 규칙 기반 피드백은 **"보조 조언"**이다. 인과 단정 금지, 근거와 함께 제시.
- 픽/스킵 로그가 기록에 없으면 3번(카드 선택 복기)은 제한적 → 가능한 범위만.

## Claude Code에 줄 첫 지시

> "런 복기 메뉴를 만들 거야. 먼저 게임 런 히스토리 파일(`...\saves\history`) 하나를 열어서, 그 안에 덱·유물·도달 층·사망 원인·카드 픽/스킵 기록이 각각 어디에 어떤 형식으로 들어있는지 쉽게 정리해서 알려줘. 그걸 보고 분석 화면을 설계하자. 나는 비개발자니까 클릭 단위로 안내해줘."
