# 기능 설계 — 성공 패턴 학습 엔진

커뮤니티/고수들의 **성공한 런 데이터**를 모아 학습하고, 그걸 근거로 추천·피드백을 강화한다.
(어드바이저의 추천 두뇌 §3, 런 복기의 2단계와 연결)

---

## 1. 목표

- "이 덱+유물 조합은 성공 사례 30개에서 평균 72% 승률" 같은 **근거 기반 추천**.
- 내 현재 덱과 성공 패턴을 **매칭**해 "다음에 이 방향으로 가면 좋다"를 제시.
- 런 복기와 만나면: "너는 여기서 무너졌는데, 성공한 사람들은 이 시점에 이렇게 했다."

## 2. 데이터 수집 (출처별 — 난이도 다름)

- **Reddit / 커뮤니티 글:** 성공 런 게시물의 덱·유물 텍스트, 덱 코드 추출. (공개 API/크롤링, 상대적으로 쉬움)
- **유튜브:** 영상 설명·댓글의 덱 코드/구성 텍스트 추출. (메타데이터는 가능. **영상 화면 속 카드 선택 자동 인식은 불가** — 화면 인식 필요, 고급)
- **공개 데이터셋/리더보드:** 성공 런 데이터베이스가 있으면 활용 (공개 여부 확인 필요).

## 3. 데이터 처리

1. 수집한 런에서 **덱 구성 + 유물 + 캐릭터 + 결과(승/패, 도달 층)** 추출.
2. 정규화된 JSON으로 저장 (앱의 카드/유물 ID 체계와 매칭).
3. 조합별로 **승률·표본 수·평균 도달층** 태깅.
4. 표본이 적은 조합은 "참고용(신뢰도 낮음)"으로 구분 — **과신 금지.**

## 4. 앱 통합

- 어드바이저: 추천 카드 옆에 "성공 사례 N건, 승률 X%" 근거 추가.
- 런 복기: 실패 런을 성공 패턴과 대조해 구체적 조언.

## 5. 솔직한 주의 (중요)

- **크롤링은 출처 약관·법적 범위 안에서.** 공개 데이터 위주, 과도한 수집·재배포 금지.
- **표본 편향 주의:** 유튜버/고수 데이터는 "잘하는 사람" 편향 → 초보 상황과 다를 수 있음.
- **상관 ≠ 인과:** "이 조합이 이겼다"가 "이 조합 때문에 이겼다"는 아님. 근거로 제시하되 단정 금지.
- **규모 큼:** 크롤링 + 정규화 + 로직 재설계가 필요한 별도 Phase. **어드바이저(Phase 1) 안정화 후 착수.**

## 6. 단계

- **A. 소규모 시범:** 한 출처(예: Reddit 성공글) 소량 수집 → JSON 정규화 → 몇 개 조합 승률 붙여보기.
- **B. 확장:** 출처 늘리고 표본 키움.
- **C. 통합:** 어드바이저·런 복기에 근거 표시 연결.

## Claude Code에 줄 첫 지시 (시범부터)

> "성공 패턴 학습을 시범 규모로 시작하고 싶어. 우선 Reddit의 Slay the Spire 성공 런 게시물에서 덱·유물 구성을 소량 수집해서, 우리 앱의 카드/유물 ID 체계에 맞춰 JSON으로 정규화하는 방법을 설계해줘. 크롤링은 공개 범위·약관 안에서만. 나는 비개발자니까 단계별로 안내해줘."
