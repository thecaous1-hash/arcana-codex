## 2. 게임 사실 (2026-07 조사 기준 — 코드 반영 전 재검증할 것)

- 인챈트는 카드에 붙는 **영구 강화 효과**. 런이 끝날 때까지 유지.
- **카드 한 장(사본)당 인챈트 하나만.** 제거·교체 불가(카드 변환 시 제외).
- 현재 **22종**. 이벤트·에인션트·유물·상점 등으로 획득.
- 인챈트마다 **카드 타입 제한**이 있을 수 있음 (예: 공격 카드 전용).
  - (1단계 실측: 제한 없음 15종 · Attack 전용 5종 · Skill 전용 1종 · "Attack, Skill" 복수 1종. `is_stackable`은 22종 전부 false.)
- 중요: **보상 화면의 후보 카드에 인챈트가 이미 붙어서 나올 수도 있음.**
  (즉 장기적으로는 "내 덱의 인챈트"뿐 아니라 "후보 카드의 인챈트"도 입력 대상.
  단, 1단계에서는 덱 쪽만 다룬다.)

## 3. 데이터 출처

- spire-codex가 인챈트를 정식 엔티티로 제공: 효과 텍스트, 카드 타입 제한,
  중복(스택) 가능 여부, 적용 가능 카드 목록. 게임 번역 파일 기반 14개 언어
  지원이므로 **한글 텍스트도 API로 받을 수 있을 것으로 예상**.
- ✅ **검증 완료(2026-07-21):** 엔드포인트 `GET https://spire-codex.com/api/enchantments?lang=kor`
  (백엔드 `backend/app/routers/enchantments.py`, 쿼리: `card_type`·`search`·`lang`).
  응답 22종, 필드: `id`(대문자 키)·`name`(한글)·`description`(한글, `[gold]`/`[blue]` 마커)·
  `description_raw`·`extra_card_text`·`card_type`(null=제한 없음)·`applicable_to`·`is_stackable`·`image_url`.
  원본 파일: `github.com/ptrlrd/spire-codex` → `data/kor/enchantments.json` (API 응답과 동일 스키마 대조 확인).
- ⚠️ **인챈트 이미지는 사용 금지(1단계 정책):** `image_url`이 `/static/` 경로라
  유물 이미지 때와 같은 robots.txt Disallow 문제. 이름·텍스트 표시만 사용.
- 주의: 게임 패치로 인챈트 효과가 바뀔 수 있음(예: Instinct 효과 변경 이력
  있음). 카드 데이터와 같은 방식으로 API를 항상 최신 기준으로 삼을 것.

## 4. 1단계 — 기록과 표시 ✅ 완료 (2026-07-21)

**목표**: 점수에는 아무 영향 없이, 덱의 카드에 인챈트를 붙였다 뗐다 하며
기록하고 화면에서 확인할 수 있게 한다.

### 작업 1-A: 현황 조사 — ✅ 완료

조사 결과(2026-07-21):
1. **덱 저장 = 이미 장별(사본별) 구조.** `state.deck` = 카드 한 장당 객체 하나
   (`index.html` `addDeck`: `state.deck.push({name})`). 강화도 장별(`state.deck[i].up` 토글).
2. **장별 인챈트 가능, 구조 변경 불필요** → 덱 항목에 선택 필드 `ench` 하나 추가로 해결.
   `save()`가 state 전체를 localStorage에 저장하므로 새로고침 유지 자동.
3. 덱 카드 그림 클릭 = 이름 기반 상세 팝업(장 구분 없음) → 인챈트 UI는
   장별 컨트롤 줄(강화/✕ 옆)에 배치하기로 결정.
4. API 검증 → §3에 기록.

### 작업 1-C: 덱 카드에 인챈트 기록 UI — ✅ 완료 (커밋 `6fa9b59`)

- 덱 셀 컨트롤 줄에 **✦ 버튼**(`enchOn()` 아닐 땐 미표시) → 인챈트 선택 모달
  (기존 `.modal-ov`/`.modal` 재사용).
- 목록은 카드 타입에 맞는 것만(`enchListFor`), 게임 규칙대로 한 장당 하나
  (재선택=교체, "인챈트 해제" 행으로 제거).
- 인챈트 카드는 ✦ 배지 + 버튼 on + 툴팁 `[인챈트: 이름]` 표시.
- 저장은 기존 `state`/`save()` 그대로 → 새로고침 유지.

## 5. 2단계 — 명백한 규칙 반영 (다음 세션, 지금은 하지 않음)

- 논란의 여지가 없는 확실한 규칙만 소수 선정해 점수에 소폭 반영.
  예: 피해 증폭 인챈트가 붙은 카드가 덱에 있으면, 그 카드를 직접
  강화하는 후보에 가산점. HP 소모형 인챈트가 여러 개면 회복 수단에 가산점.
- 규칙은 기존 맥락 지식 필드(syn/anti/mech 등)와 같은 구조로 넣어
  점수 엔진을 새로 만들지 않는다.
- 반영 전후 추천 결과 비교 리포트 필수.
