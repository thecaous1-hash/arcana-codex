# 조사 C2 — C항목 처방 3안 시뮬레이션

- 조사일자: 2026-08-28
- 기준 커밋: `2b7dbbf` (main)
- **기준선 검산: 통과 — 3448쌍 전수 비교, 불일치 0건** (중립 매개변수의 시뮬레이션 함수 vs 실제 logic.js scoreCard, finalScore·finalGrade 완전 일치)
- 성격: 숫자·사실 보고. 권고 없음. 앱 코드·데이터 무수정 (logic.js는 읽기·불러오기만).
- 재실행: `node tools/sim_c_options.js` (네트워크 불필요, 이 문서를 재생성)

## 조건

- 아키타입 1개를 강제 활성(strength=1.0)한 합성 덱 분석 객체로 채점. 덱 랜덤성 배제 목적.
- 빈 덱·유물 없음·floor=20·act=2(floorToAct(20)=2로 일관)·encounter='normal'. 이 조건에서
  덱 태그 기반 제2 안티 경로(logic.js:211, unionCount≥2)·포화 감쇠(satMult)·콤보·유물·인챈트 층은 발동하지 않음.
- 채점 풀 = 해당 캐릭터 카드 전체 + 콜로리스(getCard 우선순위로 중복 제거). 쌍 수 3448.
- **클램프 적용 후** = 실제 앱 경로: 기본점수 `cardBaseScoreVal`(전문가 앵커 ±1.0 클램프 포함).
  **클램프 적용 전** = 기본점수를 `blendRawVal`(클램프 없는 블렌드 원값)로 대체.
  구조 사실: 전문가 앵커 클램프는 기본점수(3원 블렌드) 단계에 적용되고 syn/anti 가감은 그 뒤에
  더해진다(logic.js:170→178). 따라서 앵커 클램프 자체는 syn/anti 변화량을 직접 흡수하지 않으며,
  흡수는 최종 [0,6] 절사(logic.js:555)와 등급 경계 이산화에서 발생한다. [0,6] 절사는 두 파이프라인 공통.
- 변형 구현 세부(①의 matchCount 미증가, ②의 coreHit 정의, ③의 core 우선 선택)는 스크립트 머리주석 참조.
